### How Product Cards Work (`src/components/ProductCard.jsx`)
* Displays individual bead thumbnail with gallery preview.
* Displays **`Price: On Request`** (no public prices).
* **"View details"** button navigates to the detailed view (`#product/{id}`).
* **"Enquire"** button directly opens WhatsApp with a pre-filled inquiry for that specific bead.

### How Product Details Work (`src/components/ProductDetails.jsx`)
* Interactive bead size variant selector (e.g., 22mm, 24mm, 26mm).
* 6-sided photo switcher: **Front, Back, Top, Bottom, Certificate, X-ray**.
* Clear spiritual specs: Deity, Planet, Beej Mantra, Nakshatra, and Chakra.
* **"Contact for Details via WhatsApp"** button formatted for consultation.

### Hash-based Routing in `src/App.jsx`
All navigation runs client-side via URL hash for smooth transitions and direct deep-linking:
* `#home` — Hero, sacred trust badges, and Featured Collection (1, 4, 3 Mukhi).
* `#guide` — 1–21 Mukhi spiritual reference accordion.

## 🔄 5. How the React App Integrates with the Live Website

1. When you run `npm run build` inside `shivarudraksha/`, Vite outputs:
   * `shivarudraksha/dist/index.html`
   * `shivarudraksha/dist/assets/index-[hash].js`
   * `shivarudraksha/dist/assets/index-[hash].css`
2. These files are copied into the web server public folder:
   * `public/index.html`
   * `public/assets/`
3. When visitors go to [`https://shivarudraksha.in/`](https://shivarudraksha.in/), the web server (LiteSpeed/Apache) serves `public/index.html` directly.
4. If a visitor types URLs like `/guide` or `/recommendations`, the backend automatically forwards them to `/#guide` or `/#recommendations`, keeping everything inside your React app.

## 🚀 6. Step-by-Step: Making Changes and Deploying Live

Whenever the React developer makes updates:

### Step 1 — Test Locally:
```bash
cd shivarudraksha
npm run dev
# verify changes at http://localhost:5173
```

### Step 2 — Build the Production Bundle:
```bash
npm run build
```

### Step 3 — Sync Built Files into Website Public Directory:
From the project root (PowerShell):
```powershell
Copy-Item shivarudraksha\dist\index.html public\index.html -Force
Copy-Item shivarudraksha\dist\assets\* public\assets\ -Force
```

### Step 4 — Commit & Deploy to Live Server:
From the project root:
```powershell
.\deploy.ps1 -Direct "your commit message describing the changes"
```

What `deploy.ps1 -Direct` does automatically:
1. Commits your local changes.
2. Pushes to both GitHub remotes (`rudraspirit` and `shiva-rudraksha-catalogue`).
3. Connects via SSH to the live server (`45.199.139.25`).
4. Pulls the latest files, refreshes caches, and deploys your changes immediately.

## 🔌 8. Are Products Connected to the Backend Engine?

### The Short Answer:
**No, the React frontend is currently NOT connected to the Laravel backend / database engine.**

### How Products Currently Work:
1. **Client-Side JSON Architecture (JAMstack):**
   * The React application fetches product data directly from a static JSON file:
     ```
     shivarudraksha/public/data/products.json
     ```
   * The loader in [`src/data/catalogue.js`](file:///d:/PROJECTS/WEBSITES/rudraspirit/shivarudraksha/src/data/catalogue.js) makes a client-side `fetch('data/products.json')`.
   * High-resolution 6-sided photos and lab certificates are loaded from:
     ```
     shivarudraksha/public/images/products/{product-slug}/
     ```
   * Because it reads directly from static files, the catalogue loads instantaneously, has zero database query overhead, and never fails due to database timeouts.

2. **The Built-in Admin Manager (`#admin`):**
   * The React app has a built-in admin tool at [`https://shivarudraksha.in/#admin`](https://shivarudraksha.in/#admin).
   * It is powered by [`src/components/AdminPage.jsx`](file:///d:/PROJECTS/WEBSITES/rudraspirit/shivarudraksha/src/components/AdminPage.jsx) and uses GitHub's Contents API with a fine-grained Personal Access Token to commit new photos and update `products.json` directly in the repository without needing a PHP backend.

3. **What the Laravel Backend Has:**
   * The Laravel backend in the root project (`rudraspirit`) contains a complete MySQL e-commerce engine with `Product`, `Category`, `ProductStock`, and API routes (e.g. `/api/v3/products` in `routes/api_v3.php`).
   * **Future Backend Connection (If Desired):**
     If the developer wants to connect the React frontend to the Laravel backend in the future:
     * In `src/data/catalogue.js`, change `loadProducts()` to fetch from `/api/v3/products` instead of `data/products.json`.
     * The React app already has a `normalizeProduct` function in `src/data/catalogue.js` that can map backend API fields to the component props.
